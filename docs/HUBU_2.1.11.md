## 视觉与动画保护

运行 `bun script/hubu-visual-audit.ts` 比较批准的 HUBU 基线。审计覆盖原有 CSS、图像、图标、字体、音视频、奖励/额度控制器、运动组件和消息时间线，共 **1648** 个文件；Git 符号链接按链接目标文本比较。最终结果为 **0 个改动**，完整哈希在 [visual-audit.json](hubu-2.1.11-evidence/visual-audit.json)。

另逐块审查 13 个修改过的旧 TSX 文件，56 条原有动画与时序语句全部保留。审查面板的 240ms、缓动曲线、触发条件和 reduced-motion，输入模式的 200ms 淡入淡出，ProviderTip 的 250ms/150ms、悬停延迟，以及原背景挂载条件均未修改。新增模型菜单的无延时定时调用只恢复搜索框焦点。

新增技能页和项目页复用 HUBU 组件与 `--workspace-*`、`--text-*`、`--border-*` 等现有变量。新增样式不定义动画或过渡。侧栏校徽与悟学习图标保留；品牌标题 `21px`、菜单 `14px`。新增导航项会占用相应菜单位置。

截图需等待原 `campus-settle` 动画完成后比较；动画中间帧不能作为元素消失或尺寸变化的依据。打包 UI 检查发现的新增按钮文字溢出、白底白字已在新增控件内修正，未修改旧样式文件。

## 技能目录与部署交接

见 [独立服务部署、验证和回滚说明](../deployment/hubu-skills/README.md)。拟定本机监听 `127.0.0.1:4492`，HTTPS 前缀 `/hubu-skills/`。

- 客户端只从 `HUBU_SKILL_REGISTRY_URL` 读取目录地址；不采用 KCode URL、缓存或凭据，不自动直连 GitHub。
- 正式构建必须显式给出 HTTPS 地址。本地测试允许 `CAMPUS_LOCAL_BUILD=1` 下的 loopback HTTP。
- Campus RC 的计划地址为 `https://hubu.wuxuexi.top/hubu-skills/`，可由仓库变量覆盖。它只是构建配置，**不表示服务已部署或验收通过**。
- 服务默认公开，来源仓库由服务器白名单配置；服务器只读 GitHub token 仅放服务器环境文件，不进入客户端。
- 未配置或无法连接目录时明确提示；本地与已安装技能继续使用。
- 全局翻译优先 HUBU 已配置默认模型，否则选择可用 HUBU 模型；聊天显式指定模型时精确使用该模型，找不到则报错。合法空简介保持空字符串并可缓存，不要求模型编造内容。

## 数据升级与验证方法

新增技能安装/版本/操作/任务引用数据表，保留旧表。集成测试用 HUBU 历史迁移构造旧数据库，再复制后升级；项目、会话、消息和模型设置保留，重复启动不破坏记录，原副本文件逐字节不变。未操作真实用户数据库。

主要复验命令（从相应 package 目录运行测试）：

```sh
# 仓库根目录：仅视觉保护审计
bun script/hubu-visual-audit.ts
# packages/core：真实目录与升级兼容
bun test ./test/hubu-skill-registry.integration.test.ts
# packages/app：新功能浏览器测试
bun x playwright test --config e2e/hubu-features/playwright.config.ts --workers=1
# packages/desktop：需先构建独立本地包，Electron 路径可用 CAMPUS_E2E_ELECTRON 指定
node e2e/hubu-features.mjs
```

打包使用 `--publish never`，输出独立版本目录，不覆盖旧安装包。`CAMPUS_E2E_MAIN` 可指定待验包内的 `resources/app.asar/out/main/index.js`；测试始终使用临时资料目录和本机模拟账号/模型，不改变用户安装。
