# Cinematic Reward V2 — source audit and reference decisions

2026-09-29. This brief supersedes the restrained visual direction in `REWARD_MOTION_RESEARCH.md`. Business receipts, persistence, queue priority ordering, authoritative snapshots and account APIs remain the existing implementation. User's latest instruction keeps the local interactive client and explicitly drops video recording for this round.

## What changed in the audit

The UI workspace **already has Motion 12.34.5** (`packages/ui/package.json`) and uses its `motionValue`/`attachSpring` in `motion-spring.tsx`. The earlier report checked app/desktop direct dependencies and missed UI's dependency. V2 reuses the installed framework-independent Motion `animate` via UI's `motion-timeline` export. The application is SolidJS, not React. No React runtime, R3F, Three.js, tsParticles engine or Rive asset pipeline is introduced.

## References actually inspected

- [Motion animate and sequence](https://motion.dev/docs/animate), [spring](https://motion.dev/docs/spring), [MotionValue](https://motion.dev/docs/motion-value), [AnimatePresence](https://motion.dev/docs/react-animate-presence). Adopt absolute timeline segments, keyframe overshoot, independent transforms and lifecycle cancellation. The existing event clock seeks a paused Motion sequence: card emergence, overshoot, suspended ownership beat and measured arc transfer cannot drift from numeric state when slowed. Presence is implemented by Solid's owner cleanup, not a React component. General layout animation is inappropriate for this overlay because chat layout and scroll must remain unchanged.
- [tsParticles presets catalog](https://particles.js.org/demos/presets), [presets repository](https://github.com/tsparticles/presets), [hyperspace source](https://raw.githubusercontent.com/tsparticles/presets/main/presets/hyperspace/src/options.ts), [fireworks source](https://raw.githubusercontent.com/tsparticles/presets/main/presets/fireworks/src/options.ts), [fountain source](https://raw.githubusercontent.com/tsparticles/presets/main/presets/fountain/src/options.ts). Inspected emitter quantity/rate, speed, drag/decay, finite life, trail, opacity decay, gravity and destruction. The Confetti Explosions catalog was accessible; guessed raw-source endpoints were unavailable, so no claim of inspecting its full implementation. Adopt finite convergence/burst emitters and gravity-bearing remnants. Do not copy rainbow colors, looping launchers, confetti shapes or downloaded explosion sounds. Source pages note the separate presets repository was archived; it is a reference, not a new dependency.
- [React Postprocessing Bloom](https://react-postprocessing.docs.pmnd.rs/effects/bloom), [ChromaticAberration](https://react-postprocessing.docs.pmnd.rs/effects/chromatic-aberration), [EffectGroup](https://react-postprocessing.docs.pmnd.rs/effect-group), [EffectComposer source](https://raw.githubusercontent.com/pmndrs/react-postprocessing/master/src/EffectComposer.tsx). Reviewed selective brightness thresholds, pass grouping, render scale, tone mapping guards and resource disposal. There is no current WebGL scene to postprocess. V2 uses cached additive Canvas glow/ring sprites, a vignette, foil/noise and CSS emission instead. This is an HDR-like visual treatment, **not actual HDR tone mapping or screen-space refraction**. No claim of WebGL bloom/chromatic aberration is made.
- [Rive React runtime](https://github.com/rive-app/rive-react) and [state-machine playback](https://rive.app/docs/runtimes/state-machines). State/trigger boundaries inform prepare → restore/reveal → impact → settle → confirm. The docs yielded a lightweight shell; no Rive asset/runtime was executed.

## Implementation boundaries

Default intensity is **High**. Full reset: 2600ms, restore 650–1150ms, impact 1150ms, hero/afterglow then confirmation. Reset card: 2300ms, slit 0–400ms, 3D emergence 280–800ms, ownership/foil, celebration 1100ms, transfer 1450–2000ms, count 1950–2130ms, confirmation. Only presentation timings/tier labels change; event eligibility and backend values do not.

High targets 128 reset / 96 card particles; MAX 160 / 120. Canvas preallocates a finite pool and caches radial glow and shock-front textures. No per-particle Solid state and no particle RAF. One bounded controller clock drives the canvas and seeks Motion. DPR is capped at 1.25 and raster width at 1800px. Slow frames halve particle density. Reduced Motion runs a separate fade treatment without canvas, shake, travel or 3D.

FX preview remains explicitly synthetic and opt-in (`CAMPUS_LOCAL_BUILD=1 CAMPUS_REWARD_PREVIEW=1`); normal production builds expose no debug panel. It offers replay, High/MAX, 0.25×/0.5×/1×, particle count, bloom, shockwave, screen impact, reduced motion and sound. Real account state never changes. Real receipts supersede a preview.

Sound is synthesized locally: low rise, frequency sweep, short bass impact and crystal tail. No network/audio asset dependency. Reward sound is off until opted in; the account panel and preview expose the same persisted mute preference. Each sound closes its AudioContext and disconnects nodes on completion/cancel; reduced motion skips sound. Human listening remains separate from scheduling/lifecycle tests.
